## TL;DR

Step 3 = **linearized 6-DOF MPC**: 자세 `φ` 와 각속도 `ω` 가 MPC 상태로 들어옴. 12-D state + 3-D control 의 *fully convex* (호버 주변 single-shot linearization, full SCP 반복 *없음*). 결과:

- 대부분 시나리오에서 actuator (la=10) 와 *비등하거나 살짝 낮음*
- **divert_hard 에서 최고 (56%)** — 가장 어려운 시나리오에서 Step 1/2 의 52% 대비 +4pp
- 즉 *모델 정확도가 극한 상황에서 진짜로 의미 있음* — 평소엔 Step 1/2 의 단순 모델로도 충분.

- divert_hard reasons: scp 가 *유일하게* touchdown 50/50 (Step 1/2 는 crash_tilt 1 있었음)

## 알고리즘 — 12-D 상태 + 3-D 제어

상태 (12D):
- `p` (3) — 월드 위치
- `v` (3) — 월드 속도
- `φ` (3) — body 프레임 소각도 회전벡터 (≈ 2·q_v)
- `ω` (3) — body 프레임 각속도

제어 (3D):
- `T` — 추력 크기 (N)
- `g_x, g_y` — 짐벌 각 (rad)

동역학 (호버·수직 주변 linearization):

```
v̇_x ≈ g · φ_y
v̇_y ≈ −g · φ_x
v̇_z ≈ T/m − g
φ̇ = ω
ω̇_x ≈ (m·g·L / I_xx) · (−g_y)
ω̇_y ≈ (m·g·L / I_yy) · g_x
ω̇_z ≈ 0
```

위 모든 식이 *(T, g_x, g_y, φ, ω) 에 대해 선형* → **single SOCP 솔브**, SCP iteration 불필요.

제약: 0 ≤ T ≤ T_max, |g_x|, |g_y| ≤ gimbal_limit, |φ_xy| ≤ 30° (safety, linearization validity), p_z ≥ 0, v_z ≥ −v_max_desc (soft slack 으로 초기 강하속도 허용).

비용: regulator + actuator effort + 강한 terminal (위치·속도·자세·각속도 모두).

## 왜 divert_hard 에서만 두드러지나

divert_hard = hard IC (vz 시작 −2~−5 m/s, 자세 20°까지) + hard 외란 + t=2s 패드 +10m 점프.

이 시나리오에서 vehicle 의 *자세 거동* 이 극단으로 감:
- 시작 직후 큰 자세 회복 필요
- 패드 점프 시 큰 횡 가속 요청 → 자세 명령 공격적
- 결과: 평균 |tilt| ≈ 15°+ 구간 다수 → small-angle linearization 의 *한계 영역*

그럼에도 Step 3 가 *이긴* 이유:
1. Step 1/2 (점질량 + slew) 은 자세를 *완전히 추상화* → "추력 벡터가 천천히만 바뀐다" 만 인지. *실제 자세 lag 의 메커니즘* 못 모델링.
2. Step 3 는 자세를 *명시적 state* 로 → MPC plan 이 *어떤 자세를 거쳐* 패드로 갈지 *직접* 결정. 짐벌 명령이 *그 자세를 만드는* 데 사용됨.
3. 평이한 시나리오 (hard, noisy, divert) 는 자세가 작아서 Step 1/2 의 abstraction 으로 충분 → Step 3 의 추가 정보가 marginal.
4. divert_hard 는 자세가 *진짜로 중요* → Step 3 의 자세 직접 모델링이 효과 발휘.

## 한계 — 호버 주변 단일 linearization

이 구현은 q_bar = identity (수직 자세) 와 T_bar = m·g (호버) 주변 *고정* linearization. 자세가 큰 영역에서 linearization 오차:

```
R(q) e_z = e_z + (sin θ_y, −sin θ_x, cos θ − 1) (정확)
linearized      = e_z + (θ_y,    −θ_x,    0)         (Step 3 가 보는 것)
```

12° tilt 에서: sin 12° = 0.208 vs θ = 0.209 → 차이 < 1%. 30° 에서: sin 30° = 0.5 vs θ = 0.524 → 차이 5%. 큰 tilt 에서 살짝 오차.

**Full SCP** 로 가면:
- 매 replan 마다 *현재 자세* 주변 linearize (q_bar = current q)
- 그 plan 으로 다시 한 번 linearize, 재솔브 (이게 SCP 의 *S*)
- Trust region 으로 step 한도
- 진정한 *비선형* 동역학 추종

작업량: 추가 1~2일. divert_hard 의 +4pp 가 *full SCP 로 +10pp 되리라는 보장 없음* — single-shot 이 이미 *상당 부분 효과 보고 있음*.

## 결정 — 여기서 멈출지 Full SCP 갈지

### 멈춰도 되는 근거

- divert_hard 56% 는 strong baseline (PID 18% 의 *3배*, actuator/actuator2 52% 대비 +4pp).
- 다른 시나리오는 actuator (la=10) 가 여전히 우위 → *Step 1 의 슬루 제약* 이 자세 lag 의 *충분한 abstraction* 인 시나리오가 대부분.
- 시뮬 hop_test 으로 가도 충분.

### Full SCP 까지 가야 하는 근거

- 정통 GNC 구현의 *완결성*. Falcon 9 가 실제 쓰는 것.
- divert_hard 에서 *plan-vs-rollout 진단* 으로 자세 linearization 오차 확인 → 의미 있는 추가 개선 가능성 확인 가능.
- 학습 가치 — SCP 직접 구현해보는 것 자체가 흥미.
