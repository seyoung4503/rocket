# STM32F407G-DISC1 첫 보드 bring-up (2026-06-03)

시뮬 위주로 진행해온 GNC/제어를 **실기 비행 컴퓨터**로 옮기기 위한 첫 단계.
가용한 STM32F4-Discovery(STM32F407G-DISC1)로 툴체인·플래시·GPIO·라이브
텔레메트리 경로를 검증했다. 최종 FC는 STM32H7 급 목표([hardware.md](hardware.md) A.3)
이나, F407(Cortex-M4F 168MHz, FPU)도 PID/MEKF 루프 검증에는 충분하다.

## 1. 보드/디버거 식별

- MCU: **STM32F407VGT6** — chip ID `0x413`, Flash 1MB, SRAM 128KB@`0x20000000`
  (+ CCM 64KB@`0x10000000`, 비연속), FPU/DSP, 168MHz.
- 디버거: 온보드 **ST-LINK/V2-A** (fw V2J37M26, VID:PID `0483:374B`),
  serial `066DFF575377524867033136`. MacBook에 mini-USB-B로 연결.
- `LD1`(적/녹 2색)은 ST-Link 통신 LED — SWD 활동 시 점멸(유저 LED 아님).

## 2. 온보드 주변장치 (활용 후보)

| 부품 | 정체 | 버스/핀 | 용도 |
|------|------|---------|------|
| 가속도계 | LIS3DSH 또는 LIS302DL (rev별) | SPI1 PA5/6/7, CS PE3 | 자세/기울기 (실 IMU) |
| 오디오 DAC | CS43L22 + 헤드폰잭 | I2C1 @0x4A, I2S3 | 경고음 |
| MEMS 마이크 | MP45DT02 (PDM) | I2S2 | (활용도 낮음) |
| 유저 LED ×4 | LD4 초록 PD12 / LD3 주황 PD13 / LD5 빨강 PD14 / LD6 파랑 PD15 | GPIOD | 상태표시 |
| 유저 버튼 B1 | active-high | PA0 | 발사 트리거 등 |
| USB OTG | "USB USER" micro-AB | PA11/PA12 | USB-CDC 시리얼 |

100핀 전부 P1/P2 헤더로 노출 → 외부 IMU(MPU6050/BMI088)·기압계(BMP280)·GPS·
ESC/서보(PWM) 확장 가능.

## 3. 툴체인 (macOS arm64, Homebrew)

`stlink`, `open-ocd`, `arm-none-eabi-gcc`(GCC16), `arm-none-eabi-binutils`.
PATH: `$(brew --prefix arm-none-eabi-gcc)/bin`, `.../arm-none-eabi-binutils/bin`.
주의: macOS엔 `timeout`/`stdbuf` 없음.

## 4. 검증한 것

1. **칩 식별** — `st-info --probe` → 0x413/1MB/128KB.
2. **LED** — 펌웨어 없이 OpenOCD 레지스터 직접 write로 PD12~15 러닝 라이트.
   (RCC_AHB1ENR `0x40023830` GPIODEN, MODER `0x40020C00`, BSRR `0x40020C18`.)
3. **빌드/플래시** — bare-metal(`-nostdlib`), `openocd program ... verify`.
4. **라이브 텔레메트리** — 펌웨어가 RAM `0x20000000`에 magic/heartbeat/값을
   기록, `monitor.cfg`(OpenOCD Tcl 루프)가 halt/read_memory/resume로 폴링하여
   콘솔 출력. 칩→Mac 실시간 데이터가 기존 ST-Link USB로 흐름을 확인.

## 5. 함정 두 가지 (기록용)

- **시리얼 콘솔 없음**: Discovery의 ST-Link VCP(`/dev/cu.usbmodem1303`)는 칩
  USART에 배선돼 있지 않다. 어떤 baud에서도 무신호. 진짜 UART는 외부 USB-TTL
  어댑터(PA2 TX / PA3 RX / GND) 필요. 세미호스팅(printf-over-SWD)은 openocd가
  bkpt는 인식하나 hla/ST-Link 서버 모드에서 콘솔 출력이 표면화되지 않아,
  대안으로 RAM-poll 텔레메트리를 사용.
- **SRAM 스택**(디버깅 2라운드 소요): F407은 `0x20000000`에 **128KB 연속** SRAM
  (끝 `0x20020000`), 나머지 64KB는 CCM(`0x10000000`)로 비연속. `st-info`는
  192KB로 보고해 오해 유발. 링커 `_estack`이 `0x20030000`(없는 주소)이면 Reset_
  Handler 첫 `push`에서 즉시 HardFault → main 진입 실패. `_estack ≤ 0x20020000`.

## 6. 전체 보드 셀프테스트 결과 (2026-06-03)

| 항목 | 방법 | 결과 |
|------|------|------|
| 고유 ID (96-bit) | openocd `mdw 0x1FFF7A10 3` | `00300035 33314705 32343039` (칩 유일) |
| Flash 크기 | `mdh 0x1FFF7A22` | `0x0400` = 1024 KB ✓ |
| CPUID | `mdw 0xE000ED00` | `0x410FC241` = Cortex-M4 r0p1 ✓ |
| 유저 LED ×4 | OpenOCD GPIOD write | PD12~15 러닝라이트 ✓ |
| 유저 버튼 B1 | GPIOA_IDR `0x40020010` bit0 폴링 | 누름 시 PA0 0→1 ✓ |
| **온보드 가속도계** | SPI1 + `firmware/disco_accel_test/` | **WHO_AM_I=0x3F → LIS3DSH**, 평평 시 Z≈+1000mg, 옆으로 세우면 X≈+1000mg/Z음수 — 중력 3축 측정 ✓ |
| **클럭/성능** | PLL + FPU + DWT, `firmware/disco_clock_bench/` | 16→**168MHz** 승압 ✓, 제어 업데이트 1회 547cyc=3.26µs → **최대 루프 307kHz** |
| 라이브 텔레메트리 | RAM-poll (`monitor.cfg`) | 칩→Mac 실시간 ✓ |

가속도계 센서: LIS3DSH (±2g 기본, 0.06 mg/LSB). SPI1 PA5/6/7 AF5 + CS PE3,
HSI 16MHz/APB2 16MHz/SPI baud /32 = 500kHz, SPI mode 3.

## 6.1 제어 루프 rate 여유 (벤치마크)

대표 "자세추정+PID" 업데이트(6×6 행렬-벡터 + 1차 필터 + PID, ~50 float FMA,
hard-float/FPU, -O2)를 DWT 사이클카운터로 실측:

| 클럭 | 업데이트 1회 | 최대 루프 rate |
|------|--------------|----------------|
| **168MHz + FPU** | 547 cyc = 3.26µs | **307 kHz** |
| 16MHz + FPU (환산) | 547 cyc = 34µs | ~29 kHz |

필요 자세 루프는 500Hz~1kHz → **168MHz면 ~300×, 16MHz라도 ~30× 여유.** 단순
PID는 16MHz로도 충분하나, 무거운 15-state MEKF(행렬연산 다수)까지 얹으면
168MHz+FPU 여유가 실질적. 소프트플로트 빌드는 float당 5~10× 더 느림(FPU 필수).
