# EDF roll 물리 & pluggable-propulsion 설계 노트

**작성:** 2026-05-29 21:08 (KST)
**상태:** 설계 결정 (구현 보류 — 현재 SpaceX/actuator-MPC 실험 마무리 후 진행)

## 1. 발견한 갭: 시뮬에 roll 구동 물리가 없다

현재 시뮬레이터(`src/rocketsim/dynamics.py`)는 엔진을 **순수 짐벌 추력 벡터**(크기·방향만 있는 점추력)로 모델링한다. 그 결과 roll(동체 z축 회전) 물리가 빠져 있다:

- `dynamics.py:117` — 토크 = `cross(r_engine, f_thrust_body)`. `r_engine = [0,0,-d]` 이므로 외적 결과는 `[d·fy, -d·fx, 0]` → **z(roll) 성분 항상 0**. 짐벌을 어떻게 꺾어도 pitch/yaw 토크만 생김.
- `disturbances.py:46-48` — 외란 OU 노이즈도 `out[2] = 0`으로 z축을 명시적으로 0 처리.
- 반작용 토크 / 팬 스핀 / 자이로 항 전혀 없음.

**중요한 구분:** 시뮬레이터는 *완전한 3D / 6-DOF* 다. 상태에 쿼터니언 전체(`QUAT 6:10`)와 3축 각속도(`OMEGA 10:13`)가 있고 roll 동역학도 적분된다(`omega_z`를 주면 실제로 돈다). **빠진 건 "차원"이 아니라 "roll 축을 구동하는 힘(forcing term)"** 이다. 아무도 z축에 토크를 안 넣어줘서 roll이 시작값(0)에 머무를 뿐.

근본 원인: 이름은 "EDF testbed"(`__init__.py`, `vehicle.py`)지만 동역학은 **EDF가 아니라 로켓엔진(짐벌 노즐)처럼** 짜여 있다. 노즐 가스는 축 회전을 안 만들지만, 회전하는 EDF 팬은 만든다.

## 2. 실세계 EDF roll 물리 (1차 효과)

EDF 팬을 "추력 벡터"가 아니라 **각운동량을 가진 회전 로터**로 보면 roll 현상이 외란이 아니라 *물리의 결과*로 따라 나온다:

- **반작용 토크 (지배적):** 모터가 팬을 돌리면 뉴턴 3법칙으로 기체는 반대 z축 토크를 받음. 정상상태에서 모터 토크 = 팬 공력 항력 토크 `Q`. 공력적으로 `Q ∝ ρn²D⁵`, `추력 ∝ ρn²D⁴` → `Q = thrust · D · (C_Q/C_T)`. 즉 **추력에 비례하는 roll 외란**, 컨트롤러는 측정 못 함.
- **자이로 세차:** `H_fan = I_fan·ω_fan` (동체 z축). 기체가 pitch/yaw로 돌면 `-ω × H_fan` 토크가 다른 축으로 새며 축간 커플링 발생.
- 팬 각속도는 추력에서 유도(새 상태 변수 불필요): `ω_fan = ω_max·√(thrust/max_thrust)` (추력 ∝ ω²).

수치 감각(소형 90mm급 EDF, hover 추력 ~24.5N): `Q ≈ 0.012·24.5 ≈ 0.29 N·m`. roll 관성이 `0.004 kg·m²`로 매우 작아 → roll 각가속 ~70 rad/s². **즉 roll 제어 없이는 빠르게 발산** → 실물이 카운터-로테이팅 팬이나 RCS를 쓰는 이유. 모델이 이 문제를 정직하게 드러냄.

## 3. 엔지니어링 원칙: "실세계 전부"는 불가능

실세계 모델링은 깊이가 무한(블레이드 와류, 지면효과, 모터 전기 동역학...). 규율은 **지배적 효과를 1차 원리로 넣고, 나머지는 경계 지어 외란 + 도메인 randomization, 파라미터는 실측 캘리브레이션, sim-vs-real 검증 후 반복**:

| 단계 | 방법 | 예 |
|---|---|---|
| 1차 물리 | 제1원리로 모델 직접 | 반작용 토크, 자이로, 6-DOF 강체 |
| 2차 효과 | 경계 + 도메인 randomization | 지면효과, roll 공력 감쇠, 블레이드 효과 |
| 모를 것 | 실측 캘리브레이션 | `C_Q/C_T`, `I_fan`, `ω_max` |
| 검증 | sim vs 실하드웨어 후 반복 | 갭 크면 1차로 승격 |

## 4. 결정: 별도 "세계"에 넣는다 (pluggable propulsion)

EDF roll 물리를 **지금 코드에 직접 박지 않는다.** 현재 SpaceX/actuator-MPC 실험을 먼저 마무리하고, EDF 물리는 별도의 새 "세계"에 넣는다.

**Why:**
- 지금은 EDF(팬 추력)지만 **나중엔 로켓엔진으로 전환** 예정. 로켓엔진엔 팬 반작용 토크가 없으므로 EDF 전용 물리를 공용 모델에 박으면 전환 시 들어내야 하는 부채.
- "엔진 물리를 갈아끼우며 컨트롤러가 견디는지 본다"는 **재사용 가능한 실험 노하우**를 쌓고 싶음.

**합의된 구조:**

```
┌─ 6-DOF 강체 적분기 (범용, 현재 dynamics.py 유지) ──────┐
│   상태 = pos, vel, quat, omega, + 추진 내부상태         │
│        │  force_body, torque_body 받아 적분만           │
└────────┼────────────────────────────────────────────────┘
         │ (state, cmd) → (force, torque, 내부상태 미분)
   ┌─────┴──────────────┬──────────────────────────────┐
   │  EdfPropulsion      │  RocketPropulsion (나중)      │
   │  · 팬 = 회전 로터    │  · 짐벌 노즐 = 순수 추력      │
   │  · 반작용 토크(roll) │  · TVC 서보 동역학            │
   │  · 자이로 세차       │  · 터보펌프 lag / 슬로싱      │
   │  · 스풀업 lag        │  · (팬 반작용 없음)           │
   └─────────────────────┴──────────────────────────────┘
```

- **현재 세계(로켓엔진식)** = 지금 모델 그대로. 안 건드림.
- **새 세계(EDF)** = `EdfPropulsion`만 새로 구현. 강체 적분기·컨트롤러·평가 인프라 공유.
- 나중 진짜 로켓엔진 → `RocketPropulsion`에 슬로싱·터보펌프 등 추가.

**TVC 방식 결정: 유닛 전체 짐벌** (소형 EDF 표준; 베인은 고온·침식·효율 손실). 기존 짐벌 모델(`thrust_direction_body`)과 일관 — 팬 축이 짐벌과 함께 기울어 반작용·자이로가 `dir_body` 축으로 작용 (짐벌-각운동량 커플링도 자연 발생).
